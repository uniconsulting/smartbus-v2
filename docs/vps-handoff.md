# Перенос SmartBus на VPS

Для новой установки скачайте исходники ветки `prod`. В каталоге `deploy/` лежит зашифрованный стартовый архив. Он содержит подготовленную учётную запись и настройки отправки заявок в MAX. Администратору VPS понадобится отдельный ключ расшифровки.

Сначала восстановите `/root/smartbus-handoff/smartbus-initial-data.tar.gz` по [инструкции к архиву](../deploy/SMARTBUS-INITIAL-DATA.md). Затем выполните команды ниже.

## Первая установка

Пример для Linux предполагает, что системный пользователь и группа службы называются `smartbus`. Администратор может подставить фактическое имя. Установите пакет командной строки `sqlite3`.

Выполните команды ниже из Bash под root. Они предназначены только для первого запуска на новом каталоге. При наличии `/var/lib/smartbus-v2` команда `mkdir` завершает процедуру. Для сайта с действующей базой используйте его постоянный каталог, резервную копию и существующие учётные записи. Дополнительный логин там можно создать штатной командой `pnpm admin:account`.

```bash
(
  set -euo pipefail
  umask 077
  archive=/root/smartbus-handoff/smartbus-initial-data.tar.gz
  state_dir=/var/lib/smartbus-v2
  service_user=smartbus
  service_group=smartbus

  id "$service_user" >/dev/null
  test -r "$archive"
  mkdir -m 0700 "$state_dir"
  tar -xOzf "$archive" smartbus.sqlite > "$state_dir/smartbus.sqlite"
  test "$(sqlite3 "$state_dir/smartbus.sqlite" 'PRAGMA integrity_check')" = ok
  test "$(sqlite3 "$state_dir/smartbus.sqlite" 'SELECT count(*) FROM accounts')" -eq 1
  if tar -tzf "$archive" | grep -Fx '.integration-key' >/dev/null; then
    tar -xOzf "$archive" .integration-key > "$state_dir/.integration-key"
    test "$(wc -c < "$state_dir/.integration-key")" -eq 32
  fi
  chown -R "$service_user:$service_group" "$state_dir"
)
```

Архив передаёт хеш пароля подготовленной учётной записи и закрытые настройки MAX. Храните архив как секрет. Сессия создаётся заново при первом входе. Размещайте `SMARTBUS_DATA_DIR` вне каталога сайта и сохраняйте его при обновлениях. Службе нужны права записи для SQLite, загрузок PDF и обложек.

## Служба и домен

Для установки, сборки и проверок используйте Node.js 24 и pnpm 9.15.4. Регрессионные тесты запускаются командой `node --test tests/*.test.mjs`. В каталоге исходников выполните `pnpm install --frozen-lockfile` и `pnpm run build`. Для запуска из systemd укажите `WorkingDirectory` с исходниками и `User`/`Group` с правами на каталог данных. В секцию `[Service]` добавьте:

```ini
Environment=NODE_ENV=production
Environment=SMARTBUS_DATA_DIR=/var/lib/smartbus-v2
Environment=SMARTBUS_TRUST_PROXY=1
EnvironmentFile=-/etc/smartbus/max.env
```

Для `ExecStart` используйте фактический абсолютный путь к `node`, аргументы `node_modules/next/dist/bin/next start --hostname 127.0.0.1 --port 3012` и свободный локальный порт. После изменения unit выполните `systemctl daemon-reload` и запустите службу.

`SMARTBUS_TRUST_PROXY=1` включайте, когда приложение слушает только loopback, а наружный трафик поступает через настроенный доверенный reverse proxy. В уже существующем HTTPS-блоке nginx для домена сайта с фиксированным `server_name` настройте:

```nginx
location / {
    proxy_pass http://127.0.0.1:3012;
    proxy_http_version 1.1;
    proxy_set_header Host $server_name;
    proxy_set_header X-Forwarded-Host $server_name;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $remote_addr;
    client_max_body_size 12m;
}
```

Если перед nginx стоит CDN или балансировщик, задайте его доверенные адреса в realip-модуле nginx, чтобы `$remote_addr` отражал посетителя. Установите TLS для рабочего домена, включите перенаправление с HTTP на HTTPS и проверьте конфигурацию командой `nginx -t` перед перезагрузкой прокси.

## MAX

Панель и отправка заявок обращаются к `platform-api2.max.ru` с проверкой сертификата. Если VPN прерывает соединение, сравните запрос без авторизации по умолчанию и через выбранный сетевой интерфейс (пример для macOS):

```sh
curl --cacert certs/russian_trusted_root_ca.pem -sS -o /dev/null -w '%{http_code}\n' https://platform-api2.max.ru/me
curl --interface en0 --cacert certs/russian_trusted_root_ca.pem -sS -o /dev/null -w '%{http_code}\n' https://platform-api2.max.ru/me
```

HTTP 401 без токена подтверждает, что сервер MAX доступен по HTTPS. Если работает только второй запрос, укажите имя рабочего интерфейса в `SMARTBUS_MAX_INTERFACE` в локальном окружении и перезапустите SmartBus. Настройка применяется только к MAX. На VPS по умолчанию оставьте её пустой.

При установке из закрытого архива токен и беседа уже заданы. Откройте «Интеграции» → «Проверить подключение MAX». Поле для ввода нового токена остаётся пустым — так панель скрывает сохранённое значение. Если используется другая, чистая установка с передачей через `max.env`, установите предоставленный файл с правами root. Пример для новой установки:

```bash
install -d -m 0700 -o root -g root /etc/smartbus
test ! -e /etc/smartbus/max.env && install -m 0600 -o root -g root /root/smartbus-handoff/max.env /etc/smartbus/max.env
```

После перезапуска службы админка прочитает токен из окружения и покажет его состояние без вывода самого секрета. При настройке новой интеграции без готового архива добавьте бота в неё, проверьте числовой ID и в разделе «Интеграции» выберите MAX или автоматический режим. Кнопка «Проверить подключение MAX» проверяет доступ самого бота и его присутствие в беседе. Реальную доставку подтверждает сообщение о согласованной тестовой заявке из формы сайта и статус этой заявки в журнале.

Если токен уже сохранён в самой переносимой базе, приложение использует шифротекст из записи `integrations` и соответствующий ключ. При локальном ключе передайте файл `.integration-key` из того же снимка. При внешнем ключе восстановите прежний `SMARTBUS_INTEGRATION_KEY` отдельным защищённым способом. Изменение ключа сделает ранее сохранённые токены нечитаемыми.

### Как узнать ID существующей беседы

На платформе MAX Бизнес в настройках бота разрешите добавление в групповые чаты (раздел «Приватность»). Добавьте бота в нужную беседу администратором с правами читать и отправлять сообщения. Сохраните его токен в панели либо задайте через закрытый файл окружения.

В разделе «Интеграции» под полем ID группы нажмите «Узнать ID беседы». Панель запомнит текущую позицию в очереди событий MAX и выдаст команду на пять минут. Отправьте её отдельным сообщением в нужную группу и нажмите «Проверить сообщение». Панель проверит сообщения, поступившие с сохранённой позиции, и подставит ID группы, в которой появилась команда. Проверьте поле и нажмите «Сохранить настройки».

Если у бота уже есть webhook или другое приложение получает его события через Long Polling, запросите ID у администратора действующего обработчика и введите его вручную. Он может посмотреть поле `chat_id` в событии `bot_added` или `message.recipient.chat_id` в событии `message_created` из нужной группы. Панель проверяет наличие webhook перед выдачей и проверкой команды. При Long Polling приложения работают с общей очередью, и запрос с маркером помечает предыдущие события прочитанными. [Получение ID беседы](https://dev.max.ru/docs-api/use-cases/getting-chat-id/) · [Получение событий и маркеры](https://dev.max.ru/docs-api/methods/GET/updates/)

## Приёмка

Откройте `/api/health` по рабочему HTTPS-домену. Затем в отдельном окне браузера перейдите на `https://<домен-сайта>/adpanel`. Логин и пароль для первого входа находятся в закрытом файле `admin-access.txt`; создавать учётную запись заново не нужно. Откройте «Статьи», проверьте MAX в «Интеграциях» и выйдите. Повторное открытие `/adpanel` должно привести к форме входа. Для следующих выпусков обновляйте код и перезапускайте службу с этим же постоянным каталогом данных.

## Заявки и данные

Одна и та же заявка с прежним requestId считается один раз. Для нового обращения применяются лимиты на контакт, на адрес посетителя за доверенным nginx и на весь сайт. Ответ 429 содержит Retry-After. Внешний JSON-клиент перед подтверждением получает consentRevision из GET /api/lead и возвращает его вместе с полями заявки и consent=true. При ответе 409 посетителю показывают обновлённые документы и заново получают подтверждение.

Сайт удаляет устаревшие обращения и события порциями при работе. Для очистки в периоды без трафика добавьте в пользовательский crontab сервисной учётной записи следующую строку, подставив фактический каталог приложения, путь Node и SMARTBUS_DATA_DIR.

```cron
* * * * * cd /srv/smartbus/app && SMARTBUS_DATA_DIR=/var/lib/smartbus-v2 /usr/bin/node scripts/prune-submissions.mjs
```

Оператор отдельно выполняет удаление по обращению посетителя или при более раннем достижении цели обработки, а также задаёт срок хранения закрытых резервных копий и сообщений в беседе.

## Файлы для передачи

В репозитории опубликованы исходники и зашифрованный стартовый архив. Ключ расшифровки и данные для входа передаются по закрытому каналу. Для переноса уже настроенного MAX запустите в исходной установке с действующим SMARTBUS_DATA_DIR команду `pnpm admin:export-max /путь/вне/проекта/max.env`. Она создаёт новый файл с правами 0600. Сохранение в панели, экспорт, проверка доступа к группе и успешная доставка реального сообщения — отдельные операции.
